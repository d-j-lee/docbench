# 알림 서비스 설계 노트

> 상태: 검토 중 · 담당: 플랫폼팀 · 마지막 확인 [실측] 9/29~10/2 부하 시험

## 배경

사내 알림이 메일·메신저·SMS 세 갈래로 흩어져 있어 중복 발송과 누락이 함께 생긴다.
9/29~10/2 사이 장애 두 건이 모두 같은 원인(재시도 폭주)이었다 [실측].

## 목표와 비목표

- 목표: 발송 경로 하나로 합치기, 재시도 정책 한 곳에서 관리
- 목표: 발송 결과를 사용자별로 조회 [추정] 수요는 월 2천 건
- 비목표: 마케팅 대량 발송 (별도 시스템 유지)

## 구조

### 수신 API

```http
POST /v1/notifications
Content-Type: application/json

{ "to": "user:1234", "channel": "auto", "template": "deploy-done" }
```

### 발송 작업자

| 구성 | 개수 | 비고 |
|---|---:|---|
| 큐 | 1 | 우선순위 3단 |
| 작업자 | 4 | 채널별 동시성 제한 |
| 재시도 | 최대 5회 | 지수 백오프, 상한 10분 |

### 메모

작업자 수는 부하 시험 결과를 보고 다시 정한다 [미확인].

## 위험

### 채널 공급자 장애

SMS 공급자 하나가 멈추면 큐가 밀린다. 채널별 큐를 나눌지 [결정 대기].

### 메모

공급자 계약서의 초당 한도 확인 필요 [확인 필요].
