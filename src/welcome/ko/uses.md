# 직군별 활용

> 마크다운(`.md`)으로 쓰는 문서라면 직군과 상관없이 쓸 수 있습니다. 아래 표에서 내 직군을 찾고, 그 절의 **이렇게**를 그대로 따라 해 보세요. 절이 없는 직군은 가까운 절을 따라 하면 됩니다(QA → 개발, 디자인·UX → 기획·PM, 재무·경영지원 → 데이터·AI).
> 이 문서도 연습용입니다. 적고, 보내고, 되돌려 봐도 됩니다.

## 한눈에

| 직군 | 자주 다루는 문서 | 이렇게 쓰면 좋다 |
|---|---|---|
| 개발 | 설계 문서 · ADR · API 명세 · README | 리뷰 의견을 섹션에 모아 한 번에 반영하고, 바뀐 곳만 확인 |
| 인프라·운영 | 런북 · 장애 보고서 · 점검표 | 빈칸(`[작업 후 기입]`)을 형광으로 찾고, 절차가 바뀐 이력을 남김 |
| QA | 테스트 계획 · 결과 보고 | 항목별 의견을 모아 Claude 에게 한 번에 맡기고, 결과는 **요약 복사**로 담당자에게 |
| 데이터·AI | 실험 보고서 · 모델 카드 · 지표 정의 | `[실측]` `[추정]` 표기로 주장과 근거를 나눠 읽기 |
| 서비스 기획·PM | 기획서 · PRD · 회의록 | 리뷰어마다 **제안만**으로 보내고, 기획자가 **볼 것**에서 적용·거절 |
| 디자인·UX | UX 문구 가이드 · 디자인 원칙 | 문구 하나를 골라 **이렇게 바꿔**로 바로 고쳐 쓰기 |
| 영업·사업개발 | 제안서 · 고객 FAQ | 고객별로 고칠 곳만 적고, 공통 원칙은 **늘 지킬 지시**로 |
| 마케팅·홍보 | 보도자료 · 캠페인 브리프 | 톤·금칙어를 늘 지킬 지시에 두고 매번 같은 기준으로 |
| 고객지원 | 응대 매뉴얼 · 도움말 문서 | 바뀐 정책을 폴더의 문서마다 반영하고, 한 일을 **요약 복사**로 공유 |
| 인사·교육 | 규정 · 온보딩 안내 · 교육 자료 | 개정 의견을 조항마다 달고 **제안만**으로 하나씩 적용 |
| 재무·경영지원 | 업무 지침 · 보고서 | 수치에 근거 표기를 달고, 빈칸부터 채우기 |
| 법무·컴플라이언스 | 약관 · 내부 규정 초안 | 조항마다 의견을 달고 Claude 는 제안만, 최종 판단은 사람 |
| 리더·경영진 | 주간 보고 · 전략 문서 | **읽기 정리**로 먼저 볼 곳만 펼쳐 10분 안에 핵심 |

## 개발 — 설계 문서 리뷰

리뷰 의견이 PR 댓글, 메신저, 회의록에 흩어지면 무엇이 반영됐는지 다시 찾아야 합니다.

**이렇게**

1. 저장소의 `docs/` 폴더를 엽니다. 문서는 그 자리에 있고, 기록(의견·이력)은 따로 쌓입니다.
2. 읽으면서 섹션마다 짧게 적습니다. "페이지 나누기가 빠졌다", "이 목록은 표로". 급한 것에는 ★.
3. 다 읽으면 **★만** 골라 먼저 보내고, 나머지는 리뷰가 끝난 뒤 한 번에 보냅니다.
4. **볼 것**에서 고친 섹션의 바뀐 곳을 보고 확인하거나 되돌립니다. 확인한 회차는 **요약 복사**로 커밋 메시지나 PR 설명에 붙입니다.

**얻는 것**: 의견과 반영 결과가 섹션 단위로 남습니다. 손대지 않은 줄은 줄바꿈까지 그대로라 git diff 에 고친 곳만 나옵니다.

## 인프라·운영 — 런북 정비

런북은 장애가 났을 때만 펼쳐 보게 되고, 그사이 빈칸과 낡은 절차가 쌓입니다.

**이렇게**

1. 런북 폴더를 엽니다. `[작업 후 기입]`, `TODO` 같은 빈칸이 형광으로 보이고 문서 위에 빈칸 수가 나옵니다.
2. **Claude 검토 → 제안·질문 받기**를 고르고, 범위를 같은 폴더의 문서로 넓힙니다. 문서끼리 어긋난 용어나 숫자도 짚어 줍니다.
3. 질문에는 아는 값을 답하고, 제안은 바뀐 곳을 보고 적용합니다.
4. 바뀐 절차는 **변경 이력**(왼쪽 **작업대** 아래)에 누가, 언제, 어떤 의견으로 바꿨는지 남습니다.

**얻는 것**: 장애가 나기 전에 런북이 최신이 되고, "이 절차 누가 바꿨지?"에 바로 답할 수 있습니다.

## 데이터·AI — 실험 보고서 검증

숫자가 측정값인지 추정값인지 섞여 있으면 읽는 사람이 판단할 수 없습니다.

**이렇게**

1. 근거 표기를 씁니다: `[실측]` `[문서]` `[조사]` `[추정]` `[미확인]`. 화면이 색으로 나눠 보여 줍니다.
2. **Claude 검토**를 "근거 없는 수치와 표기가 빠진 주장을 짚어 줘"라는 말과 함께 보냅니다.
3. 질문으로 돌아온 곳에는 출처를 답하고, 고침은 바뀐 곳을 확인합니다. Claude 는 표기를 지우거나 숫자를 지어내지 말라는 지시를 늘 함께 받습니다.

**얻는 것**: 숫자마다 근거가 붙은 보고서가 되고, 검토가 느낌이 아니라 근거 표기를 하나씩 짚으며 이어집니다.

## 서비스 기획·PM — 기획서 의견 모으기

리뷰어 다섯 명의 의견을 기획서 하나에 모으는 데만 반나절이 걸리기도 합니다.

**이렇게**

1. 기획서 폴더를 엽니다. 처음 저장할 때 기록 폴더를 **문서 폴더 안에 두기**로 고르면, 같은 폴더를 여는 사람끼리 결과와 이력을 함께 봅니다(git 으로 나누는 팀에 맞습니다).
2. 리뷰어는 각자 문구를 골라 그 자리에 적고, 고칠 글이 분명하면 **이렇게 바꿔**로 바꿀 글을 직접 씁니다. 보내기 전의 초안은 적은 사람에게만 보입니다.
3. 리뷰어는 다 적으면 붙일 말 한 줄("결론은 그대로, 근거만 보강")과 함께 **제안만**으로 보냅니다. 문서는 아직 그대로입니다.
4. 기획자는 **볼 것**에서 리뷰어별 회차를 보며 제안을 **적용**하거나 **거절**합니다. 리뷰 회의에서 들은 말은 기획자가 그 자리에 적어 두었다가 회의 뒤 한 번에 보내도 됩니다.

**얻는 것**: 의견 모으기, 반영, 확인이 문서 한 곳에서 끝나고, 어느 의견이 어떻게 반영됐는지 남습니다.

## 영업·마케팅 — 같은 기준으로 여러 문서

제안서와 보도자료는 문서마다 같은 톤과 금칙어를 지켜야 합니다.

**이렇게**

1. **늘 지킬 지시**에 한 번 적어 둡니다. 예: "존댓말", "경쟁사 이름은 쓰지 않는다", "수치는 출처와 함께".
2. 문서마다 고칠 곳만 적어 보내면 늘 지킬 지시가 매번 함께 갑니다.
3. 고객별 버전을 만들 때도 같은 기준이 적용되고, 회차 요약을 복사해 승인 요청에 붙입니다.

**얻는 것**: 담당자가 바뀌거나 여러 번 고쳐도 같은 기준이 매번 함께 갑니다.

## 고객지원 — 바뀐 정책을 여러 문서에

환불 기한 하나가 바뀌어도 응대 매뉴얼, 도움말, 자주 묻는 질문을 모두 찾아 고쳐야 합니다.

**이렇게**

1. 응대 문서 폴더를 열고 **Claude 검토 → 제안·질문 받기**를 고릅니다.
2. 범위를 같은 폴더의 문서(최대 10개)로 넓히고 **중점** 칸에 "환불 기한이 14일에서 30일로 바뀌었다. 예전 기한이 남은 곳을 고쳐 줘"라고 적습니다.
3. **볼 것**에서 문서별 제안을 보고 **적용**하거나 **거절**하고, 끝나면 **요약 복사**로 팀에 알립니다.

**얻는 것**: 빠뜨린 문서 없이 반영하기 쉽고, 어느 문서의 어느 문장을 고쳤는지 남습니다.

## 인사·교육 — 규정 개정

개정안은 고치는 일보다 무엇이 왜 바뀌었는지 설명하는 일이 더 오래 걸릴 때가 많습니다.

**이렇게**

1. 현재 규정을 열고 개정할 조항마다 이유와 함께 의견을 적습니다.
2. 반영 방식을 **제안만**으로 보냅니다. 문서는 그대로 두고 고친 글이 제안으로 옵니다. 바뀐 곳을 보고 하나씩 적용하거나 거절합니다.
3. 개정 회의에서는 제안 카드의 차이(지운 글·더한 글)를 그대로 띄웁니다. 적용한 결과는 **변경 이력**에 어떤 의견으로 바꿨는지와 함께 남고, DocBench 앱으로 연 git 폴더라면 마지막 커밋(HEAD)과도 비교할 수 있습니다.

**얻는 것**: 조항마다 개정 이유(의견)와 결과(바뀐 글)가 짝으로 남아 개정 공지문을 쓰기 쉽습니다.

## 법무·컴플라이언스 — 고치지 않고 짚어만 받기

약관과 규정은 한 글자를 바꿔도 무엇을 왜 바꿨는지 남아야 합니다.

**이렇게**

1. **늘 지킬 지시**에 "조항 번호와 정의된 용어는 바꾸지 않는다", "근거가 없으면 `[확인 필요]`로 둔다"를 적어 둡니다.
2. 조항마다 의견을 적고 **제안만**으로 보냅니다. 맞는지만 볼 곳은 적는 칸의 **확인만** 단추를 씁니다.
3. 제안은 사람이 바뀐 곳을 보고 **적용**하거나 **거절**합니다. 적용한 것은 어떤 의견으로 바꿨는지와 함께 이력에 남습니다.

**얻는 것**: Claude 는 짚고 제안만 하고, 바꾸는 결정은 사람이 합니다.

## 리더·경영진 — 긴 보고서 빠르게 읽기

회의 10분 전에 30쪽짜리 보고서를 받습니다.

**이렇게**

1. 문서를 열고 **Claude 검토 → 읽기 정리**를 고릅니다.
2. Claude 가 먼저 볼 섹션은 펼치고 나머지는 접어 둡니다. 문서 내용은 그대로이고 내 화면의 접기만 바뀝니다. 되돌릴 수도 있습니다.
3. 읽다가 생긴 질문은 그 자리에 적어 두었다가 회의 뒤 한 번에 보냅니다.

**얻는 것**: 핵심부터 읽고, 질문은 문서의 그 자리에 남아 작성자가 바로 답할 수 있습니다.
